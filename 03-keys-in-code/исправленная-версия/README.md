# Бот «Запись клиентов» — после разбора безопасности

## Как запустить

Нужно: Python 3.10+, пакеты `python-dotenv` и `requests` (`pip3 install python-dotenv requests`).

1. Скопируй `.env.example` в `.env` и заполни три переменные.
2. Запусти: `python3 bot.py`. Без заполненного `.env` бот объяснит, чего не хватает, и не начнёт работу.

Секреты живут только в `.env` (он в `.gitignore`, в репозиторий не попадает). В коде и в логах их нет.

## Если токен уже утёк (по шагам)

1. **Перевыпустить — первым делом.** В Telegram @BotFather: `/revoke` (или «API Token → Revoke current token») — старый токен умирает, бот получает новый. Пока токен жив, чужой человек имеет полный доступ к боту и перепискам, независимо от того, закрыли ли репозиторий.
2. Перевыпустить **все ключи, которые были в утёкших файлах**: ключ магазина, ключ Google API. Их выдают те кабинеты, где они создавались.
3. **Удалить из истории гит мало.** git rm + коммит не вычищает: старые коммиты остаются доступными (`git show <коммит>:файл`). Если репо был публичным — считай, что ключ видели. Новая история после перевыпуска ключей: удалить файл из проекта, добавить .gitignore, дальше писать чистый код. Чистку истории (`git filter-repo` / BFG) делаем отдельно, но ключи она не защищает — только перевыпуск.
4. Проверить логи бота на действие чужих: неизвестные команды, незнакомые chat_id.
5. С этой минуты сканировать репо перед каждым пушем: `git grep -E "AAH-|token|key"` или сервис проверки секретов.

## Что было заменено по сравнению с вайбкодом

- В коде нет ни одного ключа: всё приходит из окружения (`.env` на машине, переменные на хостинге).
- `.env` закрыт `.gitignore`, есть образец `.env.example` без реальных значений.
- Логи не печатают секреты: только «конфигурация загружена».
- Запросы к внешним API — с таймаутом.
