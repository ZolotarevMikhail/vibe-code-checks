# Кейс №3 — Ключи в коде и .env

Разбор вайбкод-бота, который жил в открытом репозитории вместе со всеми своими токенами. Это **демо-кейс** (учебный, не оплаченный заказ) по мотивам реальных ТЗ с Kwork. Все токены вымышленные, но проверка настоящая: команды из README находят утечки в этом же демо-репо за две минуты.

## Что в папке

- `ТЗ-ЗАКАЗЧИКА.md` — задача словами заказчика: «боты висят мёртвые, я держал код на GitHub».
- `исходник-с-ошибками/` — «репозиторий заказчика»: `bot.py` с токенами в коде, `.env` со всеми ключами, без `.gitignore`. Git-история в репо не вложена — сделай её сам одной командой перед опытами: `git init && git add -A && git commit -m first` (как было у заказчика)..
- `отчёт-разбора.md` — находки, таблица «что утекло», инструкция перевыпуска.
- `исправленная-версия/` — бот на окружении, `.gitignore`, `.env.example`, README с планом «если токен уже утёк».

## Как воспроизвести (3 минуты)

1. Утечка из репо: `cd исходник-с-ошибками && git show HEAD:.env` — git отдаёт ключи даже год спустя. Скан истории: `git log -p --all | grep -cE "AAH-|shop_live_"`.
2. Секреты в логе: `python3 bot.py` (из исходника) — все ключи печатаются в консоль до первого запроса.
3. Исправленная версия: `cd исправленная-версия && python3 bot.py` — без `.env` бот объяснит, чего не хватает, и остановится. Заполни `.env` из `.env.example` — и в логе не появится ни одного значения.
4. Проверка gitignore: `git init && git add -A`, в статусе не будет `.env`; `git check-ignore .env` подтвердит.

Нужен: Python 3.10+ и пакеты `requests`, `python-dotenv` (`pip3 install requests python-dotenv`).
