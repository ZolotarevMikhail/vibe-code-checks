# Кейс №2 — Парсер падает ночью

Разбор вайбкод-парсера цен конкурента, который по ночам умирал и оставлял пустой CSV. Это **демо-кейс** (учебный, не оплаченный заказ) по мотивам реальных ТЗ с Kwork. Ошибки в коде, поведение источника и проверка — настоящие: всё в папке воспроизводится командами из README.

## Что в папке

- `ТЗ-ЗАКАЗЧИКА.md` — задача словами заказчика.
- `исходник-с-ошибками/парсер.py` — вайбкод-версия: любая ошибка источника валит сбор, файл результата заранее открывается на перезапись.
- `исходник-с-ошибками/лог-ночной.txt` — вид ночной картины у заказчика (сгенерирован для демо, помечен внутри файла).
- `стенд/mock_api.py` — мини-сервис, изображающий источник данных: первый запрос каждой категории отвечает 429, у категории 105 второй запрос 500. Детерминированный, счётчик с запуска.
- `отчёт-разбора.md` — находки по приоритетам, таблица до/после, что исправлено.
- `исправленная-версия/парсер.py` — парсер, который переживает сбой источника.

## Как воспроизвести (5 минут)

Нужно: Python 3.10+ с библиотекой requests (`pip3 install requests`).

1. Подними источник: `python3 стенд/mock_api.py 8899` (оставь работать).
2. Сломанный прогон: `cd исходник-с-ошибками && python3 парсер.py` — увидишь крэш, а `цены-конкурентов.csv` останется только с заголовком. Проверка потери данных: создай в этом файле любую строку перед запуском — она пропадёт.
3. Исправленный прогон: `cd исправленная-версия && PARSER_TOKEN=demo-token-12345 python3 парсер.py` — увидишь повторы ответов источника в логе, в конце «файл обновлён, 74 строки».
4. Тот же стенд, те же ответы — разное поведение. Сравнивай логами двух прогонов.

На Windows команду шага 3 запусти без `PARSER_TOKEN=...` в начале строки — задай переменную в системе или просто пропусти её: парсер напомнит в логе.
